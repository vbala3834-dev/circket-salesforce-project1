CrickStats: Cricket Player Performance Tracking

Project documentation and demo guide · Version 1.0 (demo build)

1. Overview

CrickStats is a web application for recording, analysing and comparing cricket player performance. Coaches, selectors, analysts and fans can log match data, then see career statistics, form trends and head-to-head comparisons in one place.

Problem: Player stats live in spreadsheets and scorebooks, which makes trends, form and comparisons slow to produce.

Solution: A single system that captures ball-by-ball or scorecard-level data and turns it into dashboards and reports.

Goals

  • Track batting, bowling and fielding performance per match, season and career
  • Visualise form over time (rolling averages, strike rate, economy)
  • Compare players side by side
  • Support multiple formats: Test, ODI, T20 and domestic/club

Out of scope (demo build)

Live score feeds, payments, video analysis, fantasy leagues.

2. Users and Roles

Role Can do
Admin Manage users, teams, tournaments, all data
Scorer / Coach Create matches, enter scorecards, edit own team data
Analyst / Selector View dashboards, compare players, export reports
Viewer Read-only access to public stats

3. Features

  1. Player profiles: bio, role (batter, bowler, all-rounder, keeper), batting/bowling style, team history
  2. Match entry: scorecard form with innings, batting cards, bowling figures, fielding events
  3. Career stats: matches, innings, runs, average, strike rate, 50s/100s, wickets, economy, best figures
  4. Form tracker: last 5/10 innings, rolling average charts
  5. Compare players: up to 3 players across any format
  6. Leaderboards: top run-scorers, wicket-takers, best strike rates by season or tournament
  7. Filters: format, opposition, venue, season, home/away, batting position
  8. Export: CSV and PDF player reports

4. Key Metrics and Formulas

Metric Formula
Batting average Runs ÷ Dismissals
Strike rate (bat) (Runs ÷ Balls faced) × 100
Bowling average Runs conceded ÷ Wickets
Economy Runs conceded ÷ Overs bowled
Bowling strike rate Balls bowled ÷ Wickets
Boundary % (Runs from 4s and 6s ÷ Total runs) × 100
Dot-ball % (Dot balls ÷ Balls faced or bowled) × 100

Note: "not outs" are excluded from the dismissals denominator. Overs are stored as balls internally (6 balls = 1 over) to avoid decimal errors such as 4.3 overs.

6. Data Model

players: id, name, dob, country, role, batting_style, bowling_style teams: id, name, type (national/club/franchise) tournaments: id, name, format, season matches: id, tournament_id, date, venue, format, team_a_id, team_b_id, result batting_innings: id, match_id, player_id, team_id, position, runs, balls, fours, sixes, dismissal_type, bowler_id bowling_spells: id, match_id, player_id, balls_bowled, maidens, runs, wickets, wides, no_balls fielding_events: id, match_id, player_id, catches, stumpings, run_outs

Relationships: a match has many batting innings and bowling spells; a player has many innings and spells across matches; career stats are computed from these tables (or cached in a player_stats summary table).

7. API Reference (core endpoints)

Method Endpoint Purpose
POST /api/auth/login Log in, receive token
GET /api/players List/search players
GET /api/players/:id Player profile
GET /api/players/:id/stats?format=T20&season=2026 Aggregated stats
GET /api/players/:id/form?last=10 Recent innings and rolling average
GET /api/compare?ids=1,2,3&format=ODI Side-by-side comparison
POST /api/matches Create a match
POST /api/matches/:id/scorecard Submit batting, bowling and fielding data
GET /api/leaderboards?stat=runs&season=2026 Top performers
GET /api/players/:id/report.pdf Export report

9. Setup

# 1. Clone and install
git clone <repo-url> crickstats && cd crickstats
npm install

# 2. Configure environment
cp .env.example .env     # set DATABASE_URL, JWT_SECRET

# 3. Create schema and seed demo data
npm run db:migrate
npm run db:seed

# 4. Run
npm run dev              # frontend :3000, API :5000

Demo accounts (seeded): admin@crickstats.demo, coach@crickstats.demo, analyst@crickstats.demo. Change passwords before any real use.

11. Testing

  • Unit tests: stat formulas (edge cases: zero dismissals, zero wickets, partial overs)
  • API tests: auth, role permissions, scorecard validation (balls ≤ overs × 6, wickets ≤ 10)
  • UI tests: scorecard entry flow, filters, compare view
  • Data validation: totals per innings must reconcile with extras and wickets

13. Risks and Assumptions

  • Data quality depends on accurate scorecard entry; validation rules mitigate this
  • Historic data import may need cleaning (name variants, duplicate players)
  • Demo data is fictional and not real player records
